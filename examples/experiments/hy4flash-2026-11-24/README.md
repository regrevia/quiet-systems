# hy4flash 对照实验

日期 2026-11-24

模型 WorkBuddy `Hy4 flash`

任务 固定为一个移动端本地照片编辑器编辑页

视口 390 × 844 与 1440 × 844

## 实验目的

使用同一模型、同一任务、同一数据和同一视口，比较不使用 UI Guard 与使用 UI Guard 的原型。比较项包括可运行性、图片完整显示、图标操作、文案密度、视觉层级和跨视口收缩。

## 控制变量

- 任务和数据保持一致
- 模型固定为 WorkBuddy `Hy4 flash`
- 两个条件均要求单文件 HTML
- 两个条件均要求 390px 和 1440px
- 截图使用 Chromium headless、禁用 GPU、JPEG 采集后转 PNG
- 静态检查使用仓库内 `node scripts/ui-guard-review.mjs --json`

## 条件 A：baseline

提示词

> 生成一个可运行单文件 HTML：移动端本地照片编辑器编辑页。展示一张照片、五个工具一键/风格/精修/消除/重塑，当前一键，状态标准，支持撤销和下载，适配 390px 与 1440px，图片完整显示。不要读取任何 skill，不要解释，只输出唯一完整 html 代码块。

结果

WorkBuddy 首次输出在复制时仍处于生成过程，复制到的文件在 CSS 中途截断，无法运行。第二次 baseline 任务在本次记录截止时仍处于生成状态，因此不能把 A 条件视为完成样本。这个失败本身暴露了对照流程必须增加“生成完成、代码闭合、实际运行”闸门。

## 条件 B：ui-guard

提示词

> 请生成一个可运行的单文件 HTML 原型，任务固定：移动端本地照片编辑器编辑页。展示一张照片，五个工具：一键、风格、精修、消除、重塑。当前模式一键，状态标准，支持撤销和下载。适配 390px 与 1440px，图片必须完整显示。实验条件是 ui-guard，按 UI Guard 规范执行：先冻结设计合同与交互/图标清单；图标优先表达撤销、下载和返回；不做副标题、小字、解释性文字、中点分隔、重复灰色分割线、空白容器和系统原生控件；操作区使用统一圆角、紧凑层级、单一主操作。不要解释，只输出唯一一个完整 html 代码块。

结果

生成完成，代码可运行。390px 视图保留完整照片和五个工具，撤销与下载使用图标优先表达。1440px 视图把照片与工具收束为主画布和侧边操作区，图片未被裁切。

## 机器检查

两份文件都运行了仓库静态审阅脚本。A 文件因为截断未形成可运行页面，脚本没有发现规则级文本问题。B 文件指标为 2 个胶囊、1 个文字操作、2 个图标操作，当前规则未升级为 P1/P2。

这说明现有规则能识别部分结构信号，但还不能判定图片是否完整、代码是否闭合、主次操作是否合理，也不能代替真实浏览器截图。

## 结论

这组结果不能作为“UI Guard 一定比 baseline 更美”的完整因果证据，因为 baseline 没有完成。它已经证明了对照实验的必要条件，并暴露出 UI Guard 还需要补充三个硬闸门。

1. 生成物完整性闸门。检查 HTML 是否闭合、脚本是否可解析、页面是否能加载。
2. 运行时视觉闸门。在 390px 和 1440px 截图，检查图片边界、裁切、溢出和空白占比。
3. 交互证据闸门。逐项点击返回、撤销、下载和五个工具，记录状态变化和失败路径。

下一轮实验必须等待两版都进入完成态后再复制代码，并在报告中记录生成耗时、文件字节数、运行时错误和截图哈希。只有两版都通过完整性闸门，才能比较文案密度、图标优先和视觉层级等效果。
